# Contributing

Thanks for your interest in improving Grounded KB Builder.

> **Status:** this project is in pre-release review and is not yet public. External contribution
> guidelines below take effect once the repository is released.

## Ways to contribute
- **Improve the prompts** — sharper instructions, better guardrails, new entry types.
- **Extend the method docs** — clearer rules, more worked examples.
- **Report problems** — open an issue describing what went wrong and how to reproduce it.

## Ground rules
Contributions follow the same discipline the kit teaches (see `docs/method.md`). In short:
1. **Cite real, named sources** for any factual claim in docs/examples.
2. **No proprietary or confidential content** — synthetic or public data only; no internal system
   names, hostnames, identifiers, policy numbers, or business logic.
3. **Dependency-free** — prompts and docs stay tool- and model-agnostic; justify any added dependency.
4. **Small, atomic changes** — one idea per PR, like one rule per KB entry.

## Submitting a change
1. Open an issue first for anything non-trivial, so we can agree on direction.
2. Fork, create a topic branch, make your change.
3. Ensure examples still run cleanly and contain no non-public data.
4. Open a pull request describing the change and the reasoning.
